**Goal.** Turn pipeline definitions into structured deploy intents. The parsers are pure functions over raw payloads, called in Phase 4.

**Build.** Python package `dp_parsers`. Each parser returns `list[DeployIntent]`:
- `DeployIntent` fields:
  - `pipeline_ref`, `stage`
  - `mechanism`: `codedeploy`, `ecs_update`, `helm`, `terraform_apply`, `cloudformation`, `ssm_command`, `kubectl` or `unknown`
  - `target_selector`: application, deployment group, cluster/service, release/namespace, stack, or tag filter
  - `credential_mode`: `oidc`, `static_keys`, `instance_profile`, `service_role` or `unknown`
  - `has_approval`: bool
  - `has_test_stage`: bool
  - `confidence`
- **Parsers**
  - `codepipeline_structure`: from the collected pipeline JSON. Confidence 1.0.
  - `buildspec`, `appspec`.
  - `github_workflow`: YAML. Detects `aws-actions/configure-aws-credentials` with `role-to-assume` (oidc) versus `aws-access-key-id` (static_keys); `helm upgrade`, `kubectl apply`, `aws ecs update-service`, `terraform apply`; test steps by command pattern.
    - `has_approval` is true when the deploy job uses an environment with required reviewers.
    - It is also true when the triggering branch has branch protection requiring at least one review. The parser emits `approval_depends_on_branch_protection=<branch>`, and P4-06 resolves it from the GitHub branch protection records.
  - `jenkinsfile`: pattern-based, never evaluating Groovy. Detects `sh`/`bat` steps with the commands above plus `aws deploy create-deployment` and `aws ssm send-command`; `input` steps; `withAWS` and `withCredentials`; stage names matching `(?i)test`. Confidence 0.7.
  - `jenkins_config_xml`: freestyle `hudson.tasks.Shell` commands and credential bindings, same detection. Confidence 0.8.
  - `helm_values`: image repository and tag.
- A **fixture corpus** under `tests/fixtures/` with at least three positive and two negative samples per parser, including each estate pipeline's real definition.
