Before starting: read `CLAUDE.md`, confirm every dependency is `done` in `tasks/STATUS.md`, run the account guard for any AWS write.

**Goal.** An application built entirely by hand, with no IaC and no pipeline.

**Build.** Bash scripts using the AWS CLI. Every resource ID created is appended to `estate/clickops/manifest.json`.
- **IAM user `dev.juan`**
  - Access key created and stored in Secrets Manager secret `condor/harness/dev-juan` (PLANTED: AK-PIP-04).
  - Inline policy: ECR push to `condor-inventario`, `ecs:UpdateService` and `ecs:RegisterTaskDefinition` on the Inventario cluster, `iam:PassRole` for the task execution role.
  - Boundary `condor-sandbox-boundary`.
- **ECR repository `condor-inventario`**: mutable tags, scan on push disabled (PLANTED: AK-PIP-09).
- **ECS**
  - Cluster `condor-inventario`, Fargate.
  - Task definition `condor-inventario`:
    - image `condor-inventario:latest` (PLANTED: AK-PIP-09)
    - environment variable `DB_HOST=condor-tienda-db` endpoint
    - environment variable `API_TOKEN=CONDOR-CANARY-<uuid>` (PLANTED: AK-APP-03)
    - log group `/condor/inventario`
  - Service `condor-inventario`, desired 1, `app` subnets, no load balancer.
- **Database access**: the task reads Tienda's database with a read-only Postgres user created by the script (PLANTED: AK-APP-02). Keep the password in Secrets Manager `condor/inventario/db`, referenced in the task definition as a secret.
- **First image**: build and push using `dev.juan`'s keys from the operator workstation. That makes CloudTrail record a human identity.
- **No tags, and no CloudWatch alarms** (PLANTED: AK-APP-04).

**Acceptance**
- [ ] The service reaches a steady state and the log group shows periodic counts.
- [ ] `aws ecs describe-task-definition` shows the canary token in plain text. This is intentional.
- [ ] `manifest.json` lists every created resource.

**Cost limit.** USD 0.10/hour.
