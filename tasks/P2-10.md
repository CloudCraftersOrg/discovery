Before starting: read `CLAUDE.md`, confirm every dependency is `done` in `tasks/STATUS.md`, run the account guard for any AWS write.

**Goal.** The time-series and cost sources, summarised rather than copied wholesale.

**Build.** Domain: `infra`.
- **`cloudwatch`**
  - For each EC2 instance, RDS instance, ALB, NLB and ECS service found in the latest `config` run: 14-day daily statistics (average, p95, max) for the primary metrics (CPU, network in and out, request count, DB connections).
  - Emits `metric` records per resource per day.
- **`flowlogs`**
  - Incremental by checkpoint. Reads the Parquet flow logs in `condor-flowlogs-<acct>` directly with pyarrow; do not copy the files.
  - Aggregates per hour: `(src_addr, dst_addr, dst_port, protocol, action)` → packets and bytes.
  - Emits `metric` records, `resource_type=FlowAggregate`.
  - Drops link-local and AWS DNS resolver addresses.
- **`cur`**
  - On each new CUR 2.0 partition, reads Parquet and aggregates per `line_item_resource_id`, product code, usage type and day: unblended cost, amortised cost and usage amount.
  - Carries `resource_tags` for `app` and `managed-by`. Emits `metric` records.
  - Also emits a daily account total, used for reconciliation (AK-BC-01).
- **`cost_optimization_hub`**: all recommendations with estimated monthly savings, action type and resource ARN.
- **`compute_optimizer`**: EC2, ASG, EBS and RDS recommendations, with findings and projected utilisation.
- **`license_manager`**: license configurations, usage, and associated resources.
- **`wellarchitected`**: workloads, lens reviews, risk counts per pillar, and milestones.

**Acceptance**
- [ ] Unit tests: flow aggregation over a fixture Parquet file produces the expected tuples; CUR aggregation over a fixture yields a total matching the fixture sum within 0.01.
