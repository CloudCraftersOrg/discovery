Before starting: read `CLAUDE.md`, confirm every dependency is `done` in `tasks/STATUS.md`, run the account guard for any AWS write.

**Goal.** A modernization business case that reconciles to billing, where every number has a band, a lag and evidence.

**Build**
- **Spec `docs/specs/business-case.md`**, and Lambda `dp-casegen`. Horizon: 36 months, monthly granularity. Seven lines:
  1. **Baseline run-rate**: in-scope amortised monthly cost per app, from the last full 30 days of CUR, projected flat. Unattributed cost is its own row. It must reconcile to the in-scope CUR total within 1% (AK-BC-01).
  2. **Do-nothing trajectory**: baseline plus known cost events on their dates:
     - Extended-support uplift for lifecycle findings, where AWS publishes one, starting at `standard_support_end`.
     - Growth assumption: 0% by default; configurable in `casegen.yaml`.
  3. **Target run-rate**: a placeholder row, `source: "AWS Transform"`, with values `null` and status `pending_transform`. It is never estimated here (AK-BC-03).
  4. **Cost avoidance**: the sum of monetised findings (rightsizing, Savings Plans, idle resources, decommission), each entering at its `realization_lag_days`, with bands carried.
  5. **Risk of inaction**: an itemised list, with `value_usd` 0 unless the rule defines one, of:
     - lifecycle risks
     - static keys and admin roles
     - manual deploys and drift
     - shared datastore
     - unmonitored apps
     Each item has severity, affected apps and evidence IDs. The narrative text comes from a template per rule in `platform/casegen/templates/`, not generated freely.
  6. **Benefit realization schedule**: a month-by-month cumulative avoidance, as low, expected and high curves, derived from line 4's lags.
  7. **Post-migration value case**: per modernization candidate, the qualitative value drivers and the metrics to track afterwards (DORA deltas, lifecycle findings closed, static keys removed), with current values as the baseline.
- **Bands**: every monetary cell carries low, expected and high. App-level values are multiplied by membership confidence for the low band only, and that is stated as the assumption (AK-BC-02).
- **Outputs**
  - `business_case.json`, validating against `docs/contracts/business-case.schema.json` (write this schema).
  - Aurora tables `bc_line` and `bc_item`.
  - An Iceberg export.
