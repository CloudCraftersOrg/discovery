Before starting: read `CLAUDE.md`, confirm every dependency is `done` in `tasks/STATUS.md`, run the account guard for any AWS write.

**Goal.** The client-facing views, defined as code.

**Build**
- **Quick data source** on Athena workgroup `dp-analytics`. SPICE datasets over:
  - `coverage_*`
  - `mart_grouping_coverage`
  - `mart_portfolio`: per app, members, owner candidate from CODEOWNERS, baseline cost, tech stack, entry points, lifecycle flags. Build this dbt model here if absent.
  - `mart_dependencies`
  - `mart_delivery`
  - `mart_findings`
- **Dashboards** as QuickSight API definition JSON under `platform/quick/dashboards/`, deployed by `platform/quick/deploy.py`:
  1. **Coverage**: reach by domain and collector, gaps list, denied region.
  2. **Infrastructure**: resources by type and lifecycle status, backup gaps, idle resources, drift.
  3. **Application portfolio**: apps with confidence, member count and cost; platform tooling and governance shown separately; ungrouped list.
  4. **Dependencies**: app-to-app and app-to-datastore table, with the shared datastore highlighted.
  5. **Delivery**: pipeline map by CI system, DORA per app, manual deploys, credential modes.
  6. **Findings**: by domain and severity, with `value_usd` and band, and an evidence link column holding raw S3 URIs.
- **Row-level security**: none for the PoC. Record that in the PR.

**Human action.** A Quick subscription and author user are needed (P1-03 handoff). The operator grants the Quick service role access to `dp-lake`, `dp-athena-results` and KMS keys; write the exact steps in the handoff.

**Acceptance**
- [ ] `deploy.py` creates or updates all six dashboards idempotently.
- [ ] A human confirms each dashboard renders with estate data.
- [ ] Screenshot filenames are listed in the PR.
