**Goal.** Unambiguous grouping semantics before any engine is written.

**Build.** `docs/specs/grouping.md`, plus machine-readable `platform/processing/grouping/spec/rules.yaml`:
- **Application identity**: an application entity is created from the highest-precedence declared signal found.
  - Name derivation order: CloudFormation stack name → Terraform state key prefix → ECS service name → EKS namespace → ASG name → tag `app` value.
  - Names are normalised: lowercase, `condor-` prefix removed.
- **Signals and confidence**: exactly the ladder in `CLAUDE.md` section 7.
  - Runtime primitives are ECS service, EKS namespace, ELB target group and ASG.
  - Pipeline deploy target means the target of a `DeployIntent` confirmed by CloudTrail (P4-06).
- **Non-application classifications**, evaluated before application identity:
  - `platform_tooling`, defined below. Every resource in the same Terraform state file or CloudFormation stack as a `platform_tooling` instance inherits `platform_tooling`. This covers the Jenkins volume, security group and instance profile.
  - `governance`: tag `managed-by=cloud-governance`.
  - `shared_infrastructure`: a Terraform state file or stack whose resources are only networking, DNS or flow-log types (VPC, subnet, route table, NAT gateway, internet gateway, Elastic IP attached to NAT, flow log, hosted zone and its association). Individual Route 53 records that point at an app's load balancer are members of that app instead.
- **Membership expansion**
  - A resource attached to a member resource by a Config relationship of type *is attached to* or *is associated with* inherits membership at the member's confidence × 0.95. This covers an EBS volume attached to an ASG instance, or an ENI of a member.
  - Instances of an ASG inherit the ASG's membership. An EKS managed node group's ASG and instances are members of the app that owns the cluster through Terraform state.
  - A load balancer created for a Kubernetes Service is a member of that Service's namespace app at 0.90. Match on tag `service.k8s.aws/stack=<namespace>/<service>`, or on the Service's load balancer hostname.
  - An RDS instance is **not** inherited through security groups. It joins an app only through IaC membership or a flow dependency (P4-05).
- **Precedence**
  - Declared beats inferred.
  - Among declared signals, the highest confidence wins.
  - Two declared signals at the same confidence naming different apps create an `adjudication` item, and the resource is marked `conflict`.
- **Flow-log fallback**
  - Applies only to in-scope compute resources with no declared signal.
  - Assign to app X when ≥ 90% of the resource's accepted bytes over the last 7 days go to or come from members of X, with at least 100 flows. Confidence 0.50.
- **Platform tooling classification**, evaluated before grouping. A resource becomes `platform_tooling` and is excluded from app membership when either holds:
  - SSM Inventory shows one of the packages `jenkins`, `actions-runner` (or a `actions.runner.*` service), `gitlab-runner`, `teamcity`, `buildkite-agent`
  - an `instance_profile` or role is referenced as the credential of a pipeline in `DeployIntent`
  - The flow-log fallback must never assign `platform_tooling`.
- **Ungrouped**: in-scope resources with no membership after all rules. Reported as a set; ungrouped is itself a finding input.
- **Coverage metric** (AK-GRP-11): count of in-scope resources by `declared`, `inferred` (flow logs only) and `ungrouped`.
- **Worked examples** in the spec: every estate app, the worker, Jenkins and its volume, the runner, the Pagos node instances and NLB, Promo, the baseline buckets, and the network state. Each shows its expected output, matching the answer key.
