# P3-04 · Scope and self-exclusion

| Field | Value |
|---|---|
| Phase | Phase 3 · Gather and store |
| Stream | I |
| Depends | P3-02 |
| Gate | `none` |
| Paths | platform/scope/, platform/processing/stage/ |

Before starting: read `CLAUDE.md`, confirm every dependency is `done` in `tasks/STATUS.md`, run the account guard for any AWS write.

**Goal.** The platform never reports on itself or counts its own cost.

**Build**
- **`platform/scope/exclusions.yaml`**:
  - ARN patterns for platform resources that cannot be tagged, such as some CID-created resources and service-linked roles.
  - Name prefixes: `dp-`, and `cid-` if CID uses it.
  - The platform Terraform state bucket.
  - The P2-03 security group rule IDs and Resolver endpoints.
- **Scope resolver** used by the framework (`ctx.is_platform`) and the stage. The resource is excluded when any of these hold:
  - it has the tag `managed-by=discovery-platform`
  - it matches `exclusions.yaml`
  - it was created by the `dp-deployer` role, per the CloudTrail creator where known
- **CUR scope**: cost rows whose `resource_tags` have `managed-by=discovery-platform`, or whose resource ID is excluded, get `in_scope=false`.
- **Report**: an Athena view `v_scope_excluded` listing excluded resources with the matching reason.

**Acceptance**
- [ ] `v_scope_excluded` contains the discovery VPC, the platform Lambdas, `dp-raw`, the CID resources, and the peering connection.
- [ ] No resource with a `condor-` name, and no estate clickops manifest ID, appears in it.
- [ ] The sum of in-scope CUR cost plus excluded CUR cost equals the CUR total within 0.01 (AK-COV-03).
