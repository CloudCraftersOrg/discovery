Before starting: read `CLAUDE.md`, confirm every dependency is `done` in `tasks/STATUS.md`, run the account guard for any AWS write.

**Goal.** Four small, real applications whose repositories the GitHub collector can analyse, plus the harness repo.

**Build**
- Source under `estate/apps/<name>/`. Push each to a new repo in `GITHUB_ORG`: `condor-tienda`, `condor-pagos`, `condor-inventario`, `condor-reportes`, `condor-harness`.

| Repo | Stack | Behaviour | Tests |
|---|---|---|---|
| `condor-tienda` | Python 3.12, Flask, gunicorn, systemd unit | `GET /health`; `GET /checkout` calls `http://pagos.condor.internal/pay`; reads and writes table `orders` in PostgreSQL | pytest, with one test toggled by file `FAIL_BUILD` to force a failed build |
| `condor-pagos` | Node.js (current Active LTS), Express, Dockerfile, Helm chart `chart/` | `POST /pay` writes to MySQL table `payments`; `GET /health` | npm test, with the same `FAIL_BUILD` toggle |
| `condor-inventario` | Python 3.12, Dockerfile | Every 5 minutes reads Tienda's `orders` table and logs a count | pytest |
| `condor-reportes` | Java 17, Maven, `Jenkinsfile` | `GET /report` HTTP service; systemd unit | mvn test, with the same toggle |
| `condor-harness` | GitHub Actions workflows only | Built in P1-14 | — |

- **Runtime versions:** every language runtime, base image and database engine version in Tienda, Pagos, Inventario and Reportes must have more than 365 days of vendor support remaining at execution time. Verify each on the vendor's lifecycle page and list them in the PR. Otherwise they create lifecycle findings that are not in the answer key.
- **Clean repos:** `condor-pagos` and `condor-inventario` must have zero Dependabot alerts at push.
- `condor-tienda` and `condor-reportes` each pin one dependency to a version with a published GitHub Security Advisory (PLANTED: AK-APP-01).
  - Pick versions where the advisory is not exploitable without network exposure.
  - List the package, version and advisory ID in the PR.
- `CODEOWNERS` in each app repo:
  - Tienda: `@<org>/team-ecommerce`
  - Pagos: `@<org>/team-payments`
  - Inventario: none (PLANTED: AK-APP-04 context)
  - Reportes: `@<org>/team-data`
- Dependabot alerts enabled on all app repos. Branch protection on `main` for `condor-pagos` only: one required review.
- **Do not** add CI workflows here except the Pagos workflows (P1-07). Pipelines are wired in their own tasks.

**Acceptance**
- [ ] All five repos exist and contain the source.
- [ ] Each app's tests pass locally, and fail when `FAIL_BUILD` exists.
- [ ] GitHub shows Dependabot alerts on `condor-tienda` and `condor-reportes`. Alerts can take time to appear; if none after the push, report it in the PR rather than waiting.

**Gate.** A human approves the chosen vulnerable dependency versions before merge.
