Before starting: read `CLAUDE.md`, confirm every dependency is `done` in `tasks/STATUS.md`, run the account guard for any AWS write.

**Goal.** Deploy, not build: cost, rightsizing, licensing and maturity from AWS services.

**Build**
- **Cloud Intelligence Dashboards**
  - Follow the current official CID deployment for a single account, using the existing `condor-cur2` export if the current CID version supports it. Otherwise use CID's own data export stack, and record the choice in ADR-043.
  - Deploy CUDOS, CID and KPI dashboards.
  - Tag every resource it creates as platform. If CID's CloudFormation cannot take tags, list its stack names in `platform/scope/exclusions.yaml`.
- **License Manager**: license configurations for `SQL Server Standard` (per core) and `Windows Server` (per core), with automated discovery rules matching license-included instances. Do not associate manually.
- **Well-Architected Tool**
  - Workload `condor-estate` with the Well-Architected Framework lens, and the migration lens if present in the lens catalog. Record which.
  - Answer the questions from `platform/wellarchitected/answers.yaml` through the API. The Product stream writes that file from the estate design: a truthful, mediocre maturity.
  - Create a milestone.

**Acceptance**
- [ ] CID dashboards open in Quick. Screenshot in the PR, or a human confirms after the Quick handoff.
- [ ] `aws license-manager list-license-configurations` shows both configurations. Consumed licenses for Facturación appear, or the PR explains the discovery delay.
- [ ] `aws wellarchitected list-milestones --workload-id <id>` shows one milestone.
