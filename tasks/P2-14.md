**Goal.** Every AWS-native signal of how code and changes reach the estate: definitions, runs, identities, images and the API calls that prove deploys.

**Build.** Domain: `pipelines`.
- **`codepipeline`**: pipelines with full structure, executions since checkpoint with trigger and status, and action executions with their outputs.
- **`codebuild`**: projects with buildspec (inline or source path), service role ARN, and builds since checkpoint with status, source version and phases.
- **`codedeploy`**: applications, deployment groups (including ASG and EC2 tag targets), and deployments since checkpoint with creator (`user`, `autoscaling`, `codeDeployRollback`), status and revision.
- **`ecr`**: repositories with tag mutability and scan configuration; images with tags, digest, pushed-at time and last pull time.
- **`cloudtrail`**
  - Incremental by checkpoint. Reads log files from `condor-trail-<acct>`. Filters to these event names:
    - `PutImage`, `UpdateService`, `RegisterTaskDefinition`, `CreateDeployment`
    - `CreateChangeSet`, `ExecuteChangeSet`, `UpdateStack`, `CreateStack`, `DeleteStack`
    - `ModifyDBClusterParameterGroup`, `ModifyDBParameterGroup`
    - `SendCommand`, `StartPipelineExecution`, `PutApprovalResult`
    - `CreateAccessKey`, `AttachRolePolicy`, `PutRolePolicy`
    - S3 `PutObject` and `DeleteObject` on the tfstate bucket
  - Emits `event` records with `eventTime`, `eventName`, `userIdentity` (type, ARN, session issuer), `sourceIPAddress`, `userAgent`, `requestParameters`, and a subset of `responseElements`.
- **`iam`**
  - Users with access keys (ID suffix only, last 4 characters), key age and last used.
  - Roles with trust policy and attached/inline policy names; policy documents for roles used by pipelines, the Jenkins instance, and ECS or EKS.
  - Boundaries.
  - OIDC providers.
- **`tfstate_history`**: for each state object, list object versions with version ID, last-modified time and size. Joined to CloudTrail `PutObject` events later.
- **`image_trace`**
  - Emits relations from what is already collected: CodeBuild or GitHub run → pushed digest (from run outputs or ECR push time and CloudTrail), and ECR digest → running workload (ECS task `imageDigest`, Kubernetes pod `imageID`).
  - Runs after `ecr`, `ecs`, `kubernetes`, `github` and `cloudtrail` in the same schedule window.
