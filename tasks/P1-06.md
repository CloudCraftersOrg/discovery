Before starting: read `CLAUDE.md`, confirm every dependency is `done` in `tasks/STATUS.md`, run the account guard for any AWS write.

**Goal.** A healthy-looking, IaC-managed storefront with a proper pipeline and two planted defects.

**Build**
- **CloudFormation stack `condor-tienda`**, in YAML, deployed with `aws cloudformation deploy` as `condor-bootstrap`:
  - Internal ALB with an HTTP listener on 80, target group, and Route 53 record `tienda.condor.internal`.
  - ASG with launch template: Amazon Linux 2023, instance type `m5.large`, desired and minimum 2 (PLANTED: AK-INF-01, oversized for its load). CodeDeploy agent and SSM Agent installed.
  - RDS PostgreSQL `db.t4g.micro`, instance identifier `condor-tienda-db`, in the `data` subnets. Security group allows the Tienda instances and, for Inventario, the whole `app` subnet CIDR.
  - CloudWatch alarms: ALB 5xx count, and RDS CPU above 80%.
  - Tags: none. CloudFormation adds its own `aws:cloudformation:*` tags.
- **CodePipeline `condor-tienda`**, defined in the same stack:
  - Source: CodeConnections connection to `condor-tienda`, triggered by pushes to `main`.
  - Build: CodeBuild project `condor-tienda-build` running tests and zipping an artifact. Its service role has `AdministratorAccess` plus `condor-sandbox-boundary` (PLANTED: AK-PIP-05).
  - Approval: a manual approval action.
  - Deploy: CodeDeploy application `condor-tienda`, deployment group targeting the ASG.
- `buildspec.yml` and `appspec.yml` are committed to the `condor-tienda` repo.
- The connection needs a human to complete the handshake in the console. Write the steps in `tasks/HANDOFF-P1-06.md`.

**Acceptance**
- [ ] The stack reaches `CREATE_COMPLETE`.
- [ ] After the connection is approved, a push to `main` runs the pipeline, waits at approval, and deploys when approved.
- [ ] From an instance: `curl tienda.condor.internal/health` returns 200.

**Cost limit.** USD 0.40/hour.
