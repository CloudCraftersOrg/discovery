# P4-12 · Answer key evaluation harness

| Field | Value |

Before starting: read `CLAUDE.md`, confirm every dependency is `done` in `tasks/STATUS.md`, run the account guard for any AWS write.

**Goal.** One command that says whether the platform works.

**Build**
- **`answer-key/evaluate/run.py`**: loads `answer-key.yaml`, `trace/source_queries.yaml`, `trace/processed_checks.yaml`, `expected/dora.json` and `estate/verify/refs.json`.
  - Runs every check whose `checked_in_phase` ≤ the phase given by `--phase`, default 4.
  - Applies tolerances.
- **Reports**: `answer-key/evaluate/report-<run_id>.md` and `.json`, with item, status (`pass`, `fail`, `not_yet`), evidence count, and detail.
- **False positives**: lists findings, groupings and links on estate resources that match no answer-key item and are not in `tolerated_extra_findings.yaml`. Any false positive fails the run.
- **Snapshots**: `--save-snapshot <name>` copies all `mart_*` outputs to `dp-lake/evaluate/snapshots/<name>/`. Items whose `expect.state` is `pre_validation` are evaluated against the `pre-validation` snapshot once it exists, and against current marts before that.
- **Makefile target** `make evaluate PHASE=4`.

**Acceptance**
- [ ] `make evaluate PHASE=4` exits 0, with every phase ≤ 4 item passing and zero false positives.
