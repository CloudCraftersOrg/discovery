# P5-05 · Modernization candidates and AWS Transform handoff

| Field | Value |
|---|---|
| Phase | Phase 5 · Business case for AWS Transform |
| Stream | I+P |
| Depends | P5-04 |
| Gate | `human-action` |

Before starting: read `CLAUDE.md`, confirm every dependency is `done` in `tasks/STATUS.md`, run the account guard for any AWS write.

**Goal.** A package the Transform offering team can start from without re-running discovery.

**Build**
- **Candidate selection**, `platform/handoff/candidates.py`. An app or platform tooling item is a candidate when it has at least one finding of severity `high` or above in lifecycle, delivery or security, or `R-PIP-NO-PIPELINE`. Per candidate:
  - `drivers`: finding IDs
  - `current_state`: members, tech stack, CI system, DORA, lifecycle
  - `proposed_patterns`: from a fixed catalog `platform/handoff/patterns.yaml`
    - `os-upgrade`, `managed-db-migration`, `iac-adoption`, `ci-migration-oidc`, `jenkins-retirement`, `eks-upgrade`, `image-hygiene`
    - Selection rules are in the catalog. No free text.
  - `evidence_links`: raw S3 URIs through evidence IDs
  - Expected candidates (AK-BC-04):
    - Facturación: `os-upgrade`, `managed-db-migration`, `iac-adoption`
    - Inventario: `iac-adoption`, `ci-migration-oidc`, `image-hygiene`
    - Pagos: `eks-upgrade`
    - Reportes: `ci-migration-oidc`
    - Jenkins: `jenkins-retirement`
- **Handoff contract** `docs/contracts/transform-handoff.schema.json`, finalising P2-05's placeholder:
  - `engagement`: id, generated_at, source run IDs
  - `applications[]`: id, name, owner, criticality, members with ARNs, dependencies, validation status
  - `business_case`: embedded `business_case.json`
  - `modernization_candidates[]`
  - `open_items`: adjudications, disputed findings, partial validations
  - `evidence_index`: evidence ID to raw URI and hash
- **Package builder** `platform/handoff/build.py`
  - Writes `handoff-<engagement>-<date>.zip`: `handoff.json`, the workbooks as returned, and `business_case.json`.
  - Adds `README.md` generated from a template, explaining each file.
  - Output goes to `dp-lake/handoff/`.

**Human action.** A reviewer from the Transform offering team confirms the schema meets their intake needs before the task is closed. Record their name and date in the PR.

**Acceptance**
- [ ] Processed checks for AK-BC-04 and AK-BC-05 pass.
- [ ] `build.py` output validates against the schema.
- [ ] Every `evidence_links` entry resolves to an existing S3 object.
