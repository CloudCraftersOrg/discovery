Before starting: read `CLAUDE.md`, confirm every dependency is `done` in `tasks/STATUS.md`, run the account guard for any AWS write.

**Goal.** Bounded retention, a daily health check of collection, and a provable data destruction procedure for engagement close-out.

**Build**
- **Retention**
  - `dp-raw`: Object Lock governance 30 days; lifecycle expires noncurrent versions after 45 days.
  - `dp-lake`: Iceberg snapshot expiry every 7 days, run by a scheduled Athena `OPTIMIZE` and `VACUUM`.
- **Ledger audit Lambda `dp-ledger-audit`**, daily. It flags:
  - collectors with no successful run in 48 hours
  - runs with `failed` status
  - a coverage-gap count that changed by more than 20% from the previous run
  - Output: a `dp-audit` CloudWatch metric and an SNS topic `dp-alerts`. The operator subscribes.
- **`platform/ops/destroy_data.py`**
  1. Empties `dp-raw`, `dp-lake` and `dp-athena-results`, bypassing governance retention with `s3:BypassGovernanceRetention`, granted only to `dp-deployer` and only when invoked with `--confirm <acct>`.
  2. Drops the Glue database.
  3. Deletes the Aurora cluster with a final snapshot disabled.
  4. Deletes the DynamoDB tables and Secrets Manager `dp/*`.
  5. Writes `runbook/attestation-<date>.json` listing what was destroyed, with object counts before and after.
- **`runbook/data-destruction.md`**: the procedure, with the command, and the attestation template.

**Acceptance**
- [ ] `destroy_data.py --dry-run` lists every target with counts and performs no deletes.
- [ ] Invoking it without `--confirm` exits non-zero.
- [ ] The audit Lambda flags an injected stale collector.
