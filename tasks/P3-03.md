Before starting: read `CLAUDE.md`, confirm every dependency is `done` in `tasks/STATUS.md`, run the account guard for any AWS write.

**Goal.** The Glue and Athena tables that staged records and derived outputs live in.

**Build**
- **Glue database `dp_lake`**
- **Iceberg table `stg_records`** in `dp-lake-<acct>/iceberg/`
  - Columns: `run_id`, `collector`, `collector_version`, `domain`, `account_id`, `region`, `observed_at` (timestamp), `resource_type`, `resource_id`, `record_kind`, `payload` (string JSON), `payload_sha256`, `in_scope` (boolean), `raw_s3_uri`, `raw_line` (int).
  - Partitioned by `domain`, `collector`, `day(observed_at)`.
- **External table `raw_records`** over `s3://dp-raw-<acct>/raw/`: JSON SerDe with envelope columns, partition projection on `engagement`, `run_id`, `domain`, `source`, `account` and `region` - the full key layout in `CLAUDE.md` section 7, in that order. Projection rather than a crawler: the partition values are enumerable from the run ledger, so a crawler would be a scheduled cost and a source of drift for information already known. Read-only access to raw for tests and the stage.
- **Iceberg tables** for P3-06 and Phase 4 outputs: create empty `coverage`, `canonical_entity`, `canonical_relation`, `canonical_assertion`, `finding`, `validation_state`. Schemas mirror `docs/contracts/canonical-model.md`.
- **Athena workgroup `dp-analytics`**
  - Engine version 3.
  - Results to `dp-athena-results-<acct>`, SSE-KMS.
  - Enforce the workgroup configuration.
  - Per-query bytes-scanned limit of 10 GB.
- **Lake Formation**: not used. Access control is by IAM on the Glue database and buckets. Record this in the PR.

**Acceptance**
- [ ] `SHOW CREATE TABLE dp_lake.stg_records` shows an Iceberg table with the specified partitioning.
- [ ] A test `INSERT` and `SELECT` round trip works in the workgroup.
