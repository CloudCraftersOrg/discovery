Before starting: read `CLAUDE.md`, confirm every dependency is `done` in `tasks/STATUS.md`, run the account guard for any AWS write.

**Goal.** A curated, sourced table of end-of-support dates. Rules must never hard-code dates.

**Build**
- **`lifecycle.yaml`**: entries `{product, version_match, standard_support_end, extended_support_end, source_url, verified_on}` for:
  - Windows Server 2016, and the Windows Server versions in the lifecycle table
  - SQL Server 2016, 2017, 2019, 2022
  - Amazon Linux 2, Amazon Linux 2023
  - Every EKS version currently listed on the AWS EKS release calendar
  - RDS PostgreSQL and Aurora MySQL major versions in use
  - Every language runtime used by the estate apps (from P1-05's PR list)
- Jenkins is **not** in this table. Its currency is judged by `R-PIP-CI-HEALTH` from update-center data, so it never produces two findings.
- **Fill every date from the vendor's official page at execution time**, with `source_url`. No date comes from memory.
- **Collector `lifecycle`**, domain `infra`: loads the YAML and emits one `resource` record per entry, `resource_type=Reference::Lifecycle`. It fails the run if any `verified_on` is older than 90 days.

**Acceptance**
- [ ] Schema validation passes; every entry has a `source_url`.
- [ ] A human reviewer spot-checks five dates against their sources.
