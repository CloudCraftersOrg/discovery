Before starting: read `CLAUDE.md`, confirm every dependency is `done` in `tasks/STATUS.md`, run the account guard for any AWS write.

**Goal.** Decommission candidates that can never be produced from a single signal or from incomplete coverage.

**Build.** Rule `R-DEC-CANDIDATE`, applied to in-scope compute resources that are ungrouped or belong to an app with zero dependencies. A resource is a candidate only when **all three** signals hold over the last 14 days:
1. CloudWatch CPU p95 below 2%, taken daily.
2. Zero accepted flows in or out, excluding link-local addresses.
3. No Config configuration changes, and no deploy-class CloudTrail events targeting it.

**Guards**
- Coverage proof. Each signal's source must be `reached` for the resource's region in `coverage_reach`. A missing source means `insufficient_evidence`, not a candidate.
- A single signal never produces a candidate.
- The output is never a delete action. The finding's `recommended_action` is the staged plan below, and `requires_signoff=true`.

**Output fields**
- Staged plan: stop, observe 14 days, snapshot, then terminate after sign-off.
- `business_cycle_note`: "confirm no monthly or quarterly usage before terminate".
- Attached resources: EBS volumes and Elastic IPs.

**Acceptance**
- [ ] Unit tests: a fixture with two of three signals is not a candidate; a fixture with a missing flow-log source yields `insufficient_evidence`.
- [ ] The processed check for AK-DEC-01 passes for Promo 2024, and no other estate resource is a candidate.
