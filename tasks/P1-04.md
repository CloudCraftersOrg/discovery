Before starting: read `CLAUDE.md`, confirm every dependency is `done` in `tasks/STATUS.md`, run the account guard for any AWS write.

**Goal.** One VPC for the whole account (ADR-044-network-consolidation), holding the estate now and reserving room for the platform later, plus the Promo 2024 plant and the canary resource in the denied region.

**Build.** Terraform, applied as `condor-bootstrap`, `force_destroy = true` on every bucket. No tags except where stated.
- **VPC `condor-vpc`** in `HOME_REGION`, CIDR `10.20.0.0/16`, two AZs:
  - Public subnets (`10.20.0.0/24`, `10.20.1.0/24`) hold the NAT gateway only. One NAT gateway, to save cost. No workload in public subnets.
  - Private subnets `app` (`10.20.10.0/24`, `10.20.11.0/24`) and `data` (`10.20.20.0/24`, `10.20.21.0/24`) — unchanged addressing from the pre-consolidation design, so P1-11's existing Jenkins security-group rule (scoped to `10.20.0.0/16`) needs no edit.
  - **`promo` subnet** (`10.20.30.0/24`, single AZ, isolated): stands in for the old second-region `condor-promo` VPC. Its own route table, associated only with this subnet, with **no `0.0.0.0/0` route** — this is what P1-12's planted findings (AK-COV-04, AK-INF-07, AK-PIP-08) now live in, minus the "wrong region" characteristic.
  - **Reserve `10.20.128.0/18`**, unused in this task, for the platform's collector/data/firewall subnets when platform work starts (P2-01). Document the reservation in `docs/adr/ADR-044-network-consolidation.md`; do not carve it up here.
  - Route 53 private hosted zone `condor.internal`, associated with this VPC.
  - Flow logs: all traffic, to `condor-flowlogs-<acct>`, Parquet, hourly partitions.
- **Canary in `DENIED_REGION`**: SSM parameter `/condor/canary`, value `denied-region`. Unaffected by the consolidation — this was never a VPC element.
- **Outputs**: VPC ID, subnet IDs (including `promo` and the reserved platform CIDR), hosted zone ID, NAT public IP. Write them to `estate/verify/refs.json` under `network`, and mirror `vpc_id` plus each subnet ID to SSM Parameter Store under `/condor/network/*` so a later platform task can read them without touching estate state.

**Acceptance**
- [ ] `terraform validate` passes and apply succeeds.
- [ ] No route table on the `promo` subnet has a `0.0.0.0/0` route.
- [ ] `aws ec2 describe-flow-logs` shows active flow logs for the VPC.
- [ ] `terraform destroy` followed by `terraform apply` succeeds with no manual cleanup (Route 53 zone, NAT, flow logs all recreate cleanly).
