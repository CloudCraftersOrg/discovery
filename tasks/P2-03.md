# P2-03 · Private path to the estate

| Field | Value |
|---|---|
| Phase | Phase 2 · Build the collectors |
| Stream | I |
| Depends | P2-01, P1-07, P1-11 |
| Gate | `approve-apply` |
| Paths | platform/terraform/estate-link/ |

Before starting: read `CLAUDE.md`, confirm every dependency is `done` in `tasks/STATUS.md`, run the account guard for any AWS write.

**Goal.** Collectors reach the Pagos EKS private API and Jenkins, and nothing else inside the estate.

**Build**
- **VPC peering** `dp-discovery` ↔ `condor-estate`, with routes only for `collector` subnets to `10.20.10.0/23` (the estate `app` subnets). The peering and the estate-side route live in platform Terraform, as `dp-deployer`. Record this in `docs/adr/ADR-041-estate-link.md`.
- **Estate security group rules**, managed by platform Terraform using separate `aws_vpc_security_group_ingress_rule` resources with platform tags. Do not edit estate Terraform.
  - EKS cluster security group: 443 from `dp-collector`'s CIDRs.
  - `condor-jenkins` security group: 8080 from the same CIDRs.
  - These rule resources are platform resources and excluded from scope.
- **DNS**
  - Associate `condor.internal` with `dp-discovery`, through a cross-VPC association in the same account.
  - EKS private endpoint: create a Route 53 Resolver outbound endpoint in `dp-discovery` and an inbound endpoint in `condor-estate` (inbound in the `app` subnets, platform-tagged).
  - Add a forwarding rule for the cluster endpoint's hostname domain, associated with `dp-discovery`.
- **Test Lambda `dp-estate-probe`**: resolve and TCP-connect to the EKS endpoint on 443 and to `jenkins.condor.internal:8080`. Also try `tienda.condor.internal:80`, which must fail.

**Acceptance**
- [ ] The probe returns `{"eks": "ok", "jenkins": "ok", "tienda": "blocked"}`.

**Stop and ask if** the EKS endpoint hostname does not resolve through the forwarding rule. Do not make the endpoint public.

**Cost limit.** USD 0.30/hour.
