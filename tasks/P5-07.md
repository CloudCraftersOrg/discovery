# P5-07 · End-to-end rebuild, cost, runbook and demo

| Field | Value |
|---|---|
| Phase | Phase 5 · Business case for AWS Transform |
| Stream | I |
| Depends | P5-05, P5-06 |
| Gate | `human-action` |
| Paths | runbook/, Makefile |

Before starting: read `CLAUDE.md`, confirm every dependency is `done` in `tasks/STATUS.md`, run the account guard for any AWS write.

**Goal.** Prove the whole thing is repeatable by someone who did not build it.

**Build**
- **Make targets**
  - `make estate-up`, `make platform-up`, `make run-cycle`, `make validate-scenario`, `make evaluate PHASE=5`, `make handoff`, `make platform-down`, `make estate-down`.
  - Each target calls the guard and prints its hourly cost estimate before any apply.
- **Teardown**
  - `estate-down` destroys Terraform roots and CloudFormation stacks, then deletes clickops resources from `manifest.json` in reverse order.
  - `platform-down` runs `destroy_data.py --confirm` first.
- **`runbook/runbook.md`**
  - Prerequisites: operator access, GitHub org owner, Quick subscription.
  - Every make target, in order, with expected duration and the wait gate (P1-16).
  - Troubleshooting for the ten most likely failures observed during the build.
- **`runbook/demo-script.md`**: a 30-minute demo flow through the seven dashboards, the workbooks and the handoff package, with talking points tied to answer-key items.
- **`runbook/cost.md`**: measured hourly and monthly run cost of estate and platform separately, from CUR filtered by tags and the manifest, and how to pause (scale-to-zero targets).
- **Rebuild test**
  1. Destroy both estate and platform.
  2. Rebuild from the runbook.
  3. Pass P1-16.
  4. Run `make evaluate PHASE=5`.

**Human action.** An engineer outside the four contributors runs the rebuild from the runbook alone, and records the time taken and every point where they needed help. Fix the runbook for each of those points.

**Acceptance**
- [ ] `make evaluate PHASE=5` passes on the rebuilt environment, with zero false positives.
- [ ] The attestation from `destroy_data.py` is produced for the torn-down platform.
- [ ] The outside engineer's notes are committed as `runbook/rebuild-notes-<date>.md`, with all issues resolved or ticketed.
