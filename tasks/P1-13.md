Before starting: read `CLAUDE.md`, confirm every dependency is `done` in `tasks/STATUS.md`, run the account guard for any AWS write.

**Goal.** Human-identity changes that bypass Pagos' pipeline, made after history recording has started.

**Build**
- **IAM user `dev.maria`**
  - Access key stored in Secrets Manager `condor/harness/dev-maria` (PLANTED: AK-PIP-04).
  - Policy: read and write on `condor-tfstate-<acct>/pagos/*`, plus the permissions needed to modify `condor-pagos-params`.
  - Boundary attached.
- **Laptop apply** (PLANTED: AK-PIP-03). As `dev.maria`, from the operator workstation:
  - Change a harmless Pagos Terraform variable: the node group `max_size` from 2 to 3.
  - Run `terraform apply`. That writes the state object.
  - Commit nothing to `condor-pagos`. This change deliberately has no CI run.
- **Console-style drift** (PLANTED: AK-INF-08). As `dev.maria`, use the CLI to change a parameter in `condor-pagos-params` that Terraform manages, for example `max_connections` to 200. Do not update Terraform.
- Record both timestamps in `estate/harness/ledger.jsonl` with `kind: planted_change`.

**Acceptance**
- [ ] The state bucket shows a new object version, and the trail contains a `PutObject` data event for it with the `dev.maria` principal. Allow up to 15 minutes for delivery.
- [ ] `terraform plan` run as `condor-bootstrap` shows drift on the parameter group.
- [ ] `uv run estate/verify/check_planted.py --only P1-13` exits 0.

**Stop and ask if** `estate/verify/history-start.json` from P1-15 does not exist. These changes must happen after history start.
