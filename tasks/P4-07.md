# P4-07 · Finding rules

| Field | Value |
|---|---|
| Phase | Phase 4 · Process for dashboards |
| Stream | P |
| Depends | P4-05, P4-06, P2-11 |
| Gate | `review` |
| Paths | platform/processing/rules/, docs/rules/ |

Before starting: read `CLAUDE.md`, confirm every dependency is `done` in `tasks/STATUS.md`, run the account guard for any AWS write.

**Goal.** Every finding in the answer key produced by a declared, tested rule.

**Build**
- **Rule catalog `docs/rules/*.yaml`**, one file per rule, validating against `finding-rule.schema.json`. Each rule has a SQL (Athena or Aurora) or Python `logic_ref`, and unit fixtures. Required rules and their logic:

| Rule ID | Logic | Answer key |
|---|---|---|
| R-INF-RIGHTSIZE | Compute Optimizer or Cost Optimization Hub rightsizing recommendation exists for a member resource | AK-INF-01 |
| R-INF-SP-COVERAGE | CUR shows no Savings Plans usage, and Cost Optimization Hub has a Savings Plans recommendation | AK-INF-02 |
| R-INF-LIFECYCLE | Product version matched to `lifecycle.yaml`; severity by days to `standard_support_end`: past = critical, under 180 days = high, under 365 days = medium | AK-INF-03, 04, 05 |
| R-INF-NO-BACKUP | Non-root EBS volume attached to an in-scope instance that is not in an ASG, with no AWS Backup protection and no snapshot in 7 days; or an RDS or Aurora resource with backup retention 0 | AK-INF-06 |
| R-INF-IDLE | Unattached EBS volume, or unassociated Elastic IP | AK-INF-07 |
| R-INF-DRIFT | CloudTrail shows a modify event on a Terraform-managed resource by a principal that is neither a pipeline credential nor the Terraform CI role, after the latest write of that resource's state file | AK-INF-08 |
| R-INF-LICENSE | License Manager consumption, or SSM Inventory, shows SQL Server or Windows license-included | AK-INF-09 |
| R-APP-VULN-DEP | Open Dependabot alert on an app repo | AK-APP-01 |
| R-APP-SHARED-DB | `shared_datastore=true` | AK-APP-02 |
| R-APP-PLAINTEXT-SECRET | A `DP::Redaction` event on a task definition, pod spec, or pipeline definition | AK-APP-03 |
| R-APP-UNMONITORED | App with no CloudWatch alarm whose dimensions reference any member | AK-APP-04 |
| R-PIP-STATIC-KEYS | IAM user with an active access key used within 90 days, or a Jenkins credential of an AWS type | AK-PIP-04 |
| R-PIP-ADMIN-ROLE | A role that is a CodeBuild service role, a pipeline `DeployIntent` credential, or the instance profile of `platform_tooling`, which has `AdministratorAccess` or a policy with `"Action": "*"` | AK-PIP-05 |
| R-PIP-NO-APPROVAL | A confirmed deploy intent with `has_approval=false` and mechanism other than `ssm_command` | AK-PIP-06 |
| R-PIP-NOT-AS-CODE | A Jenkins job whose configuration is not derived from a Jenkinsfile in a collected repo | AK-PIP-07 |
| R-PIP-DEAD | A pipeline whose deploy target does not exist, or with no execution in 90 days | AK-PIP-08 |
| R-PIP-IMAGE-HYGIENE | ECR repo with mutable tags, or scan off; or a running workload referencing tag `latest` | AK-PIP-09 |
| R-PIP-CI-HEALTH | Jenkins version older than the current LTS by ≥ 2 lines, a plugin with a matched advisory, or executors on the controller > 0 | AK-PIP-10 |
| R-PIP-NO-PIPELINE | An app with no `deploys_to` relation | AK-PIP-11 |
| R-MAT-WA | Well-Architected high-risk count per pillar, recorded as information | AK-MAT-01 |

- **Metrics**, computed by the same engine and written as `assertion` rows, not findings:

| Metric ID | Logic | Answer key |
|---|---|---|
| M-IAC-COVERAGE | Every in-scope resource Config records gets `iac_status`: `managed` if in a CloudFormation stack or tfstate; `derived` if created by a parent resource (ASG instances, EKS node group instances, controller-created load balancers, attached ENIs and volumes), inheriting the parent's managed or unmanaged status; `unmanaged` otherwise. Coverage is managed ÷ (managed + unmanaged), counting derived resources with their parent. The top-level unmanaged set must equal the Config-recordable entries of `estate/clickops/manifest.json`. | AK-INF-10 |
| M-TECH-STACK | Per app, languages from GitHub repo languages of linked repos, plus runtime images from ECS and Kubernetes, plus SSM Inventory application names | AK-APP-05 |
| M-ENTRY-POINTS | Per app, Route 53 records resolving to member load balancers, with their listeners and ports | AK-APP-06 |

- **Engine, Lambda `dp-rules`**: runs every catalog rule and writes `finding` rows with evidence IDs. `value_usd` and the band are written by P4-09. Until then, rows are written to a staging table `finding_pending`, never to `finding`, because `finding` columns are `NOT NULL`.
- **dbt mart `mart_findings`**.

**Acceptance**
- [ ] Each rule's unit fixtures pass.
- [ ] Processed checks for every AK-INF, AK-APP and AK-PIP item pass, including the three metrics.
- [ ] No additional findings exist on estate resources beyond the answer key, with one exception. Rules fed by external recommendation or advisory services (`R-INF-RIGHTSIZE`, `R-INF-SP-COVERAGE`, `R-APP-VULN-DEP`) may produce extra findings, because those feeds change over time. They are listed by rule in `answer-key/trace/tolerated_extra_findings.yaml`. Any other extra needs a human-approved entry in that file.
