# P4-02 · Identity resolution

| Field | Value |
|---|---|
| Phase | Phase 4 · Process for dashboards |
| Stream | I |
| Depends | P4-01, P1-16 |
| Gate | `none` |

Before starting: read `CLAUDE.md`, confirm every dependency is `done` in `tasks/STATUS.md`, run the account guard for any AWS write.

**Goal.** One entity per real thing, however many sources mention it.

**Build**
- **dbt staging models**: flatten `stg_records` into typed views per source. The key extraction models:
  - `stg_keys` with `(source, resource_id, key_type, key_value, observed_at)`, for every key type in the canonical model.
  - Instance ID from Config, SSM (`ssm_node_id` equals the instance ID for EC2), ASG and ELB targets, and CUR resource ID.
  - ENI and private IP from Config and flow logs; image digest from ECR, ECS and Kubernetes; pod UID; hostname from SSM and Route 53.
- **Lambda `dp-identity`**
  - **Tier 0**, deterministic, confidence 1.0: identical ARN, or identical instance ID or resource ID across sources.
  - **Tier 1**, confidence 0.95:
    - ENI ↔ instance through Config's attachment relationship.
    - Private IP ↔ ENI where the IP was assigned during the flow window. Use Config history `valid_from` and `valid_to`, never the current assignment only.
    - Image digest ↔ ECR image.
  - **Tier 2**, confidence 0.7: hostname match only. Never auto-linked. Writes to `adjudication` with candidates.
  - Writes `entity`, `identity_link`, and `evidence` rows linking back to `raw_s3_uri` and `raw_line`.
- **Ground truth fixture** `platform/processing/identity/tests/fixtures/truth.json`: 200 records across sources, generated from a synthetic estate with known entity IDs. It includes reused private IPs and a replaced ASG instance.
- **CI test**: precision ≥ 0.95 and recall ≥ 0.90 on the fixture (AK-QLT-01).

**Acceptance**
- [ ] `pytest platform/processing/identity` passes, including the precision and recall test.
- [ ] Integration:
  - Each of the two Reportes ASG instances resolves to one entity carrying Config, SSM, ELB target, CUR and flow-log keys.
  - The worker resolves with no SSM key.
