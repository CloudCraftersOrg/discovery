Before starting: read `CLAUDE.md`, confirm every dependency is `done` in `tasks/STATUS.md`, run the account guard for any AWS write.

**Goal.** A repository every later task can work in safely, plus the deployment identities that keep estate and platform evidence separate in CloudTrail.

**Read first.** `CLAUDE.md`.

**Revised for the estate-only pass (ADR-044-network-consolidation).** `dp-deployer` and its state bucket are not created here — deferred to the first platform task. `condor-bootstrap` does not hold `AdministratorAccess`: the operator's own session (`AIDiscoveryAccess`, scoped to `condor-*`/`dp-*` resource names) cannot attach that AWS-managed policy to anything it creates, so `condor-bootstrap` instead carries a customer-managed policy, `condor-bootstrap-access`, scoped the same way — see `docs/adr/ADR-045-bootstrap-identity.md`.

**Build**
- Directory layout, each with a `README.md` stating its purpose in one paragraph:
  - `estate/iac/`, `estate/clickops/`, `estate/apps/`, `estate/harness/`, `estate/verify/`
  - `platform/terraform/`, `platform/collectors/`, `platform/processing/`, `platform/dbt/`, `platform/db/`, `platform/quick/`, `platform/validation/`, `platform/casegen/`, `platform/handoff/`
  - `answer-key/`, `docs/adr/`, `docs/contracts/`, `runbook/`
- `scripts/guard.sh <estate|platform>`: runs `aws sts get-caller-identity`. Exits non-zero unless the account equals `$CONDOR_ACCOUNT_ID` and the assumed role name is `condor-bootstrap` (estate) or `dp-deployer` (platform, once it exists).
- Root `Makefile` with targets `lint`, `test`, `guard-estate`, `guard-platform`, `apply-estate`, `destroy-estate`. Every AWS-writing target depends on the matching guard target. `destroy-estate` runs `terraform destroy` for every `estate/iac/*` layer in reverse dependency order — the whole point of the one-VPC design is that this and `apply-estate` are cheap to run repeatedly.
- `.pre-commit-config.yaml`: ruff, terraform fmt, gitleaks. `.gitignore` covers `.terraform/`, `*.tfstate*`, `.env*`, `*.pem`.
- `estate/iac/bootstrap/` Terraform, applied with the operator's `AIDiscoveryAccess` profile (`personal-aidiscovery`), one time only:
  - State bucket `condor-tfstate-<acct>`: versioned, SSE-KMS, public access blocked, `force_destroy = true`. Tags: `managed-by=cloud-governance` only.
  - Role `condor-bootstrap`, trusting the operator principal given as a variable, with the customer-managed policy `condor-bootstrap-access` (estate-scoped: ec2/rds/ecs/eks/ssm/codepipeline/codebuild/codedeploy account-wide; s3/iam/secretsmanager/route53 scoped to `condor-*`; config/cloudtrail/budgets read+write for account telemetry) and permissions boundary `condor-sandbox-boundary`.
  - Policy `condor-sandbox-boundary`:
    - Allow `*` on resources in `$CONDOR_ACCOUNT_ID`.
    - Deny `organizations:*`, `account:*` and `iam:CreateUser` except for users named `dev.*` and `svc.*`.
    - Deny any action on the bootstrap state object itself.
  - AWS Budgets monthly budget with alerts at 50%, 80% and 100% of a variable `monthly_budget_usd`. Operator sets it.
- `tasks/STATUS.md` already exists from the task pack. Do not regenerate it; set P1-01 to `done` when merged.

**Acceptance**
- [ ] `make lint` passes.
- [ ] `scripts/guard.sh estate` passes with `AWS_PROFILE=condor-bootstrap`.
- [ ] `aws iam get-role --role-name condor-bootstrap` shows the boundary attached.
- [ ] `aws budgets describe-budgets` lists the budget.
- [ ] `make destroy-estate` followed by `make apply-estate` succeeds with no manual cleanup step.

**Out of scope.** Any estate or platform workload. `dp-deployer` and its state bucket (added when platform work starts).

**Stop and ask if** the operator principal is not provided, or the Organization's service control policies block creating IAM users or Budgets in this account.
